# Keycloak Material 3 Theme

[English](README.md) | **Русский**

![Material 3 Expressive для Keycloak](docs/hero.png)

Тема [Material 3 Expressive](https://m3.material.io/) для Keycloak: страницы входа **и**
личный кабинет (Account Console). Вход по passkey как основной сценарий, полная
адаптивность, автоматическая светлая/тёмная схема — и развёртывание без пересборки
Keycloak: это обычный каталог темы (или компактный образ-носитель), монтируемый в
официальный образ Keycloak.

## Почему эта тема

- **Точное следование Material 3 Expressive — вплоть до пикселя.** Цветовая палитра,
  типографика Google Sans, геометрия навигационной рельсы, формы компонентов и слои
  состояний сняты непосредственно с [m3.material.io](https://m3.material.io/) — эталонной
  реализации Google — в светлой и тёмной схемах. Развёрнутая тема выглядит как продукт
  Google, а не как его приближение.
- **Каждое взаимодействие анимировано.** Появление и уход карточки, раскрытие
  парольной секции, переходы между страницами кабинета, выдвижное меню, слои состояний
  при наведении, даже плавное сворачивание брендовой панели при сужении окна — всё
  подчинено системе движения Material (стандартная кривая
  `cubic-bezier(0.2, 0, 0, 1)`, выверенные длительности). Пользователи с
  `prefers-reduced-motion` получают мгновенный интерфейс без анимации. Эти гарантии не
  декларативны: выделенный набор моушн-тестов проверяет их в CI на каждом коммите.
- **Passkey-first UX аутентификации.** Кнопка passkey — единственное залитое, самое
  заметное действие; провайдеры идентификации следуют за ней тональными круглыми
  кнопками; форма логина и пароля свёрнута, пока не понадобится (и раскрывается
  автоматически, если она — единственный способ входа или после неудачной попытки).
  Поддерживается условный интерфейс WebAuthn (автозаполнение passkey браузером).
- **Адаптивность на любом экране.** Личный кабинет показывает навигационную рельсу на
  широких экранах, сворачивает её в верхнюю панель с модальным меню на средних и
  превращается в нижнюю навигационную панель на телефонах — то же адаптивное поведение,
  что и у m3.material.io. Страница входа на десктопе дополняет карточку декоративной
  брендовой панелью и плавно убирает её на узких окнах.
- **Развёртывание без пересборки.** Никаких `kc.sh build`, упаковки в JAR, тулчейна
  Keycloakify или собственного образа Keycloak. Смонтируйте каталог — или позвольте
  опубликованному мультиархитектурному образу-носителю наполнить общий том — и
  переключите настройку рилма.
- **Ничего специфичного для инсталляции не зашито.** Брендинг берётся из рилма во время
  выполнения (отображаемое имя рилма в шапке кабинета и на брендовой панели входа);
  строки переопределяются per-realm штатным механизмом локализации Keycloak.
- **Протестирована как продукт, а не как таблица стилей.** Сквозной Playwright-набор
  (76 проверок: отрисовка, навигация, темизация, i18n, движение, регрессии доступности)
  выполняется в CI против Keycloak 26.0 и 26.3 перед публикацией любого образа.
- **Продуманные детали во всём.** Ручной переключатель светлой/тёмной темы, запоминающий
  выбор на страницах входа и в кабинете; стабильный отступ под полосу прокрутки —
  страницы никогда не дёргаются; индикатор загрузки в стиле M3, открывающий кабинет
  только после полной сборки; исправленные ошибочные русские переводы «passkey» из
  апстрима; расширяемая иконография провайдеров идентификации.

## Обзор возможностей

- **Оба пользовательских интерфейса** — страницы входа и личный кабинет `keycloak.v3`
  используют единую дизайн-систему (консоль администратора намеренно не тронута).
  Оформлены все сценарии входа: регистрация, сброс пароля, OTP, WebAuthn,
  `select-authenticator`, подтверждение выхода и страницы ошибок.
- **Типографика** — Google Sans / Google Sans Text, загружаются с CDN Google Fonts одной
  строкой `@import` в начале каждого CSS-файла. Если сторонние CDN недопустимы в вашем
  окружении (приватность / GDPR), удалите эту строку — тема откатится на Roboto и
  системные шрифты.
- **Иконки провайдеров идентификации** — Google, GitHub, GitLab и Telegram из коробки,
  сопоставление по alias провайдера; добавление провайдера — один SVG-файл без правок
  шаблонов ([подробности ниже](#иконки-провайдеров-идентификации)).
- **Локализация** — английские и русские строки собственного интерфейса темы; остальные
  локали корректно откатываются на штатные переводы Keycloak.
- **Поддержка IdP-first онбординга** — встроенный диалог помощи объясняет пользователям
  сценарий «сначала вход через провайдера, потом passkey», его текст переопределяется
  per-realm.

## Совместимость

Разработана и протестирована на **Keycloak 26.3** (образ quay.io). Тема входа расширяет
встроенную `base`, тема кабинета — `keycloak.v3`, поэтому подойдёт любой 26.x. Кнопка
passkey использует preview-функцию `passkeys` (см. ниже); без неё тема полностью
работоспособна — кнопка просто не отображается.

## Установка

Тема — обычный каталог, который оказывается смонтированным в
`/opt/keycloak/themes/material3` внутри официального образа Keycloak: без `kc.sh build`
и без собственного образа Keycloak. Выберите удобный способ доставки.

### Вариант A — образ темы (рекомендуется)

Тема поставляется компактным образом-носителем
(`ghcr.io/nd4y/keycloak-material3-theme`, busybox + файлы темы, мультиархитектурный).
При старте он копирует тему в общий том и завершается; Keycloak монтирует этот том.
На хосте размещать нечего — всё приходит из реестров, а обновление темы — это
`docker compose pull` + повторный деплой:

```yaml
# docker-compose.yml
volumes:
  material3-theme:

services:
  theme:
    image: ghcr.io/nd4y/keycloak-material3-theme:latest
    restart: "no"
    network_mode: "none"   # образ только копирует файлы — сеть не нужна
    volumes:
      - material3-theme:/target

  keycloak:
    image: quay.io/keycloak/keycloak:26.3
    command: start
    depends_on:
      theme:
        condition: service_completed_successfully
    volumes:
      - material3-theme:/opt/keycloak/themes/material3:ro
    # ... остальная ваша конфигурация
```

Kubernetes — та же идея через init-контейнер:

```yaml
initContainers:
  - name: material3-theme
    image: ghcr.io/nd4y/keycloak-material3-theme:latest
    command: ["sh", "-c", "cp -a /theme/material3/. /target/"]
    volumeMounts:
      - { name: material3-theme, mountPath: /target }
containers:
  - name: keycloak
    volumeMounts:
      - { name: material3-theme, mountPath: /opt/keycloak/themes/material3, readOnly: true }
volumes:
  - { name: material3-theme, emptyDir: {} }
```

Теги: `latest` (ветка main), `X.Y.Z` / `X.Y` (релизы), `sha-<commit>` для пиннинга.

### Вариант B — bind-mount каталога

Клонируйте репозиторий и смонтируйте тему напрямую:

```yaml
services:
  keycloak:
    image: quay.io/keycloak/keycloak:26.3
    command: start
    volumes:
      - ./keycloak-material3-theme/theme/material3:/opt/keycloak/themes/material3:ro
```

Bare metal: скопируйте `theme/material3` в `/opt/keycloak/themes/material3`.

## Настройка Keycloak

Всё нижеописанное — конфигурация рилма/сервера; самой теме этап сборки не нужен.

### 1. Переключите рилм на тему

**Realm settings → Themes**:

- *Login theme* → `material3`
- *Account theme* → `material3`
- *Admin theme* оставьте как есть (консоль администратора намеренно не темизируется).

В production-режиме темы кэшируются; после обновления файлов темы перезапустите Keycloak
(при простом переключении настройки рилма это не требуется).

### 2. Локализация

**Realm settings → Localization**:

- *Internationalization* → Enabled
- *Supported locales* → English, Русский (и любые другие — собственные строки темы есть
  в en/ru; остальные локали откатываются на штатные переводы Keycloak)

Это же включает переключатель языка на карточке входа.

### 3. Passkeys (главная кнопка)

Кнопка passkey использует встроенную поддержку passkeys в Keycloak (preview в 26.x,
требуется ≥ 26.2):

1. Запустите Keycloak с включённой функцией:

   ```yaml
   environment:
     KC_FEATURES: passkeys
   ```

2. **Authentication → Policies → WebAuthn Passwordless Policy**:
   - *Enable passkeys* → On
   - рекомендуется: *Requires discoverable credential* → Yes,
     *User verification requirement* → required

3. Дайте пользователям зарегистрировать passkey: **Authentication → Required actions** →
   включите *Webauthn Register Passwordless*, либо пользователи добавят его сами в
   кабинете в разделе *Безопасность входа → Вход*.

С активной функцией страница входа отображает залитую кнопку *Войти с passkey* и
дополнительно предлагает passkey через автозаполнение имени пользователя браузером
(условный интерфейс). На старых серверах (или с выключенной функцией) тема деградирует
корректно — кнопка просто не рендерится. Работают и стандартный browser flow, и
кастомные flow, сохраняющие штатную форму *Username Password Form*.

### 4. Провайдеры идентификации

Добавляйте провайдеров в **Identity providers** как обычно. Страница входа показывает по
круглой кнопке на провайдера; иконки сопоставляются по **alias** провайдера (`google`,
`github`, `gitlab`, `telegram` — из коробки; всё остальное откатывается на нейтральную
иконку ключа — см. [Иконки провайдеров идентификации](#иконки-провайдеров-идентификации)).

### 5. Модель регистрации

Тема поддерживает оба сценария онбординга:

- **Открытая саморегистрация**: включите **Realm settings → Login → User registration** —
  карточка входа покажет ссылку «Новый пользователь? Регистрация» и форму регистрации в
  стиле Material.
- **IdP-first онбординг** (без формы регистрации): оставьте регистрацию выключенной —
  аккаунты будут создаваться при первом входе через провайдера идентификации. **Диалог
  помощи** на карточке входа (кнопка «?») объясняет пользователям именно это: сначала
  войдите через любого из предложенных провайдеров, затем при желании настройте passkey
  или пароль (с опциональным OTP) в настройках аккаунта.

Чтобы переформулировать диалог помощи (или любую другую строку) для своего рилма без
форка темы, используйте **Realm settings → Localization → Realm overrides** и
переопределите ключи `m3HelpTitle`, `m3HelpBody1`, `m3HelpBody2`.

## Иконки провайдеров идентификации

Иконки лежат в
[`theme/material3/login/resources/img/providers/`](theme/material3/login/resources/img/providers/)
и сопоставляются по **alias** провайдера в вашем рилме:

```
providers/
  google.svg      ← alias "google"
  github.svg      ← alias "github"
  gitlab.svg      ← alias "gitlab"
  telegram.svg    ← alias "telegram"
  oidc.svg        ← запасная для alias без собственного файла
```

Чтобы добавить иконку нового провайдера, положите квадратный SVG с именем `<alias>.svg`
в этот каталог — больше ничего менять не нужно. Провайдер без иконки автоматически
получает нейтральную иконку ключа (`oidc.svg`).

## Смена цветовой палитры

Все цвета — CSS-переменные. Значения по умолчанию сняты с самого
[m3.material.io](https://m3.material.io/) (светлый primary `#6442D6`, тёмный `#9F86FF`):

- вход: [`theme/material3/login/resources/css/material3.css`](theme/material3/login/resources/css/material3.css) (токены `--m3-*`, блоки светлой и тёмной схем в начале файла)
- кабинет: [`theme/material3/account/resources/css/material3-account.css`](theme/material3/account/resources/css/material3-account.css)

Для ребрендинга сгенерируйте палитру из собственного seed-цвета в
[Material Theme Builder](https://material-foundation.github.io/material-theme-builder/) и
замените значения токенов — вёрстка нигде не ссылается на «сырые» цвета.

Собственные строки интерфейса (подписи кнопок, подсказки) лежат в
`theme/material3/login/messages/messages_{en,ru}.properties`; новые локали добавляются
файлами `messages_<lang>.properties` и перечислением локали в `theme.properties`.

## Разработка

Готовый dev-стенд с демо-рилмом (тестовые провайдеры, включённые passkeys, пользователь
`demo`/`demo1234`):

```bash
docker compose -f dev/docker-compose.dev.yml up
# → http://localhost:8080/realms/demo/account/  (пользовательский UI)
# → http://localhost:8080/admin/                (admin/admin)
```

Стенд работает в `start-dev` с отключённым кэшированием тем, поэтому правки шаблонов и
CSS применяются по обновлению страницы. Скриншоты README генерируются
[`dev/screenshots.py`](dev/screenshots.py), hero-изображение —
[`dev/promo.py`](dev/promo.py), GIF с демонстрацией анимаций —
[`dev/motion_gif.py`](dev/motion_gif.py) (всё на Playwright; для GIF нужен ffmpeg). Сквозной набор тестов
([`dev/test_theme.py`](dev/test_theme.py)) — отрисовка, навигация, темизация, i18n и
моушн-проверки — выполняется в CI против Keycloak 26.0 и 26.3 перед сборкой образа.

При выпуске изменений CSS или JS повышайте query-параметр `?v=` в обоих файлах
`theme.properties` — URL-ы Keycloak `/resources/<hash>/` меняются с версией сервера, а не
с содержимым темы, и без повышения браузеры продолжают отдавать закэшированные месяц
назад ассеты.
